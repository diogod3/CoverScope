# CoverScope v0.2.0-beta.1

This beta moves CoverScope from coverage inspection to reviewing committed branch changes through four connected questions: **What changed? How did it change? How is it verified? What might it affect?**

## Highlights

- **Committed comparisons:** choose a solution/project and a local target reference, then compare the common ancestor with the checked-out commit. Review changed files, logical types, members, and xUnit definitions.
- **Source and coverage together:** a shared explorer opens changed files in Diff by default, with reviewed/baseline views and member navigation. Git metadata is hidden. Change highlighting stays in the code area; neutral gutters show line numbers, coverage, hits, and branch details.
- **Branch coverage:** inspect all reported code, changed files, or changed executable lines. Totals follow the selected range. Compatible reports merge, duplicate attachments are counted once, and original collection scopes remain available.
- **Navigable relationships:** changed objects are shown by default, including disconnected types. Add related unchanged objects, pan/zoom, fit the graph, select side-panel details, or double-click to open a type. Interfaces and implementations are grouped; test types have a double outline and a Tests caption.
- **Focused formatting:** findings default to changed files, are grouped by rule/file, and make line-ending noise optional with an explicit count. Discovered configuration paths are labelled as candidates.
- **Visible loading:** folder browsing, target validation, and repository setup show loading indicators. Start run opens preparation immediately and then shows execution progress. Panels have usable minimum sizes and internal scrolling.
- **Saved evidence for people and agents:** reopen run history, export a compact Markdown summary, or inspect full JSON evidence with captured source, declarations, relationships, diagnostics, and tool output.
- **Independent outcomes and cancellation:** failed tests can coexist with available coverage and formatting. Cancelling an active attempt discards its analysis and retains the cancelled run record. Unresolved stopping or persistence failures remain visible and block conflicting collection.

## Install and run

Follow the [README's installation steps](../../README.md#installation) to install `DD3.CoverScope.Tool` version `0.2.0-beta.1` from NuGet.org and launch it. The README covers requirements and getting started; the [review guide](../review-guide.md) explains the controls, evidence, and reporting problems.

## Behaviour changes from 0.1.x

- A command-line target opens explicit setup; it no longer starts collection automatically.
- Reviews require committed changes, a clean worktree, and an available comparison reference. CoverScope does not fetch or alter Git branches.
- Records and analysis use `CoverScope/reviews-v2` beneath local application data. Legacy `.coverscope/reports` evidence is not imported or migrated, and existing legacy files are left untouched.
- Saved snapshots retain their captured source. Older snapshots within this workflow cannot show hit counts, per-line branches, or source that was not recorded at collection time.

## Known limitations

- The current test profile is xUnit v2 through VSTest with Coverlet; declaration indexing covers loaded C# source. Razor markup and generated/SDK output are outside declaration counts even when collectors report their coverage.
- Relationships are direct static references, not runtime impact, resolved dependency-injection bindings, or per-test coverage attribution. Coverage shows execution, not assertion quality.
- Missing dependencies, unsupported source/configurations, or baseline/index failures can leave evidence incomplete. Package-audit diagnostics remain visible without independently invalidating the index.
- Coverage merging checks reported structural identities; reports do not supply binary checksums. Incompatible overlaps remain separate. Changed-line coverage excludes context and deleted lines and has no method total.
- Formatting uses its default project configuration; the run's build configuration applies to tests and indexing. Changed-range filtering does not establish when a finding was introduced.
- Preparation before run creation has no active-run cancel control. Cancelling later does not undo external side effects already caused by builds or tests.
- Uncommitted comparisons, legacy report migration/import, Stryker integration, and a direct agent API are outside this beta.
