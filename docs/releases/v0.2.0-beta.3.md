# CoverScope v0.2.0-beta.3

This beta keeps source, related types, and tests together so you can follow a change without repeatedly scrolling between code and the graph.

## What's changed

- **Persistent type review:** keep the graph beside source, adjust its width, or collapse it into a left rail while concentrating on code. Expanding restores its navigation state. Back/forward controls retain each visit's source context.
- **Partial-file tabs:** switch between a type's files while retaining revision and scroll position. The main file appears first; conventional partials use shorter suffix labels with full-path tooltips.
- **Test source alongside code:** open a statically related test definition beside production source. On narrow screens, switch between them with a return control. Parameterized executions share a definition; ambiguous execution mappings do not produce source links.
- **Return to your review:** the Review navigation entry returns to the workspace after visiting Overview, Changes, or Verification.
- **More room for the graph:** the overview graph uses the full width by default, with an optional changed-types list.
- **Deliberate graph zoom:** use Alt + wheel or the zoom buttons. Ordinary wheel scrolling no longer zooms the graph.

## Update

```text
dotnet tool update --global DD3.CoverScope.Tool --version 0.2.0-beta.3 --source https://api.nuget.org/v3/index.json
coverscope
```

For a first installation, follow the [README](../../README.md#installation).

## Compatibility and validation

Existing saved reviews in the current workflow remain readable. Reopen a saved run to use the new workspace; no new analysis is required. Available source and test details depend on what the run captured. This release does not add measured per-line test attribution: related tests are identified through static relationships.

The workspace changes passed build, all 61 .NET tests, JavaScript interaction checks, package inspection, and installed-tool smoke tests on Windows, Linux, and macOS before merging. The release workflow validates the versioned package again before publication. Automated checks do not establish every live layout or interaction. See the [review guide](../review-guide.md) for controls and evidence limits.
